# `ui/styles.css`

> Framework-free stylesheet for the Kumaru browser UI, including theme variables, layout, sidebar controls, markdown output, and responsive behavior.

**Read this when:** you need to change the theme, adjust layout density, add a UI state class, or understand why a chat message renders the way it does.

---

## What it does

`ui/styles.css` styles the static UI served by Kumaru. It has no preprocessor and no build step. The selectors target the elements and classes in `ui/index.html` plus message markup generated by `ui/app.js`.

## Why it exists

The UI is intentionally auditable. Operators can change colors, spacing, or responsive behavior by editing one CSS file and refreshing the browser. This avoids npm dependencies, generated assets, and frontend build failures during local model work.

## Mental model

The stylesheet has four layers:

1. Design tokens in `:root`.
2. Global reset and application layout.
3. Component blocks for sidebar, messages, markdown, and composer.
4. Utilities and responsive rules.

Most visual changes should start in `:root`; structural changes usually require matching HTML and JavaScript changes.

## How to customize it

### Change the theme colours

Change custom properties rather than individual rules:

```css
:root {
  --bg: #101014;
  --bg-panel: #181820;
  --accent: #b48cff;
  --accent-dim: #4b376d;
}
```

Refresh the browser; no build is required.

### Make the sidebar wider

Change the grid column width:

```css
#app { display: grid; grid-template-columns: 360px 1fr; height: 100vh; }
```

Check that `.kv dd` still ellipsizes long model ids.

### Keep the sidebar visible on narrow screens

Replace the mobile rule with a stacked sidebar:

```css
@media (max-width: 860px) {
  #app { grid-template-columns: 1fr; grid-template-rows: auto 1fr; }
  #sidebar { display: flex; max-height: 45vh; }
}
```

Then test model-swap controls on a small viewport.

### Add styling for a new message role

If `app.js` starts rendering `messageEl("tool", ...)`, add:

```css
.msg.tool .avatar {
  background: var(--bg-elevated);
  color: var(--warn);
  border: 1px solid var(--border);
}
```

Also update `messageEl()` to choose an appropriate avatar label.

### Change markdown rendering appearance

The renderer emits plain tags such as `<p>`, `<h1>`, `<ul>`, `<pre><code>`, and `<blockquote>` inside `.bubble`. Change only `.bubble ...` selectors to avoid affecting sidebar controls.

## Failure modes

| Symptom | Likely cause | Fix |
|---|---|---|
| Theme change only affects some elements | You edited one rule instead of a shared custom property. | Move the color/spacing decision into `:root` and use `var(...)`. |
| Assistant markdown looks unstyled | `renderMarkdown()` emitted tags not covered by `.bubble` selectors. | Add `.bubble <tag>` rules or change the renderer output. |
| Copy buttons always visible | `.copy-btn` opacity or `.bubble pre:hover .copy-btn` changed. | Restore hidden-by-default opacity and hover rule. |
| Long model names break the sidebar | `.kv dd` overflow rules were removed. | Restore `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`. |
| Composer grows over the whole screen | `#input` max-height or auto-resize behavior changed. | Keep `max-height: 200px` in CSS and matching JS resize cap. |
| Sidebar disappears on desktop | Viewport is under 860px or media query changed. | Adjust or remove the breakpoint rule. |
| Range sliders look different across browsers | WebKit and Firefox use different thumb pseudo-elements. | Update both `::-webkit-slider-thumb` and `::-moz-range-thumb`. |
