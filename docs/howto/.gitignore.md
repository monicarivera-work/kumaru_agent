# `.gitignore`

> Keeps everything Kumaru generates (model weights, benchmark runs, training outputs, logs, caches) out of git, while keeping the small data files the project needs.

**Read this when:** `git status` shows files you did not mean to commit, a file you *did* mean to commit is missing from it, or you are adding a feature that writes files.

---

## What it does

git skips every path that matches a rule here: it does not show it as untracked, and `git add -A` does not stage it. Files that git already tracks are not affected.

## Why it exists

A working Kumaru folder holds far more than the source:

- **Model weights**: a single GGUF file for `qwen36` is 17.7 GB. GitHub rejects any file over 100 MB, and git history keeps every committed byte forever.
- **Outputs**: every benchmark run, training run and llama-server log.
- **Environment**: `.venv\` holds several GB once PyTorch is installed, and rebuilding it with `setup.ps1` is the reliable way to recreate it anyway.

The rule of thumb behind the file: **commit what a person wrote; ignore what a program produced or downloaded.** Anything ignored can be regenerated by a command.

## Mental model

Each block answers "which program produced these files?":

| Block | Rules | Produced by |
|---|---|---|
| Python | `__pycache__/`, `*.py[cod]`, `*.egg-info/`, `.eggs/`, `build/`, `dist/` | The interpreter and `pip install -e .` |
| | `.venv/`, `venv/` | `scripts\setup.ps1` |
| | `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/` | pytest, mypy, ruff |
| | `tests/.scratch/` | The `scratch_dir` fixture in `tests\conftest.py` |
| Kumaru runtime | `/tools/llama.cpp/` | `scripts\get-llama-server.ps1` (the leading `/` matches only the top-level `tools` folder) |
| | `runs/` | Benchmarks (`runs\bench\`), training (`runs\<name>\`, from `output_dir`), llama-server logs (`runs\logs\`) |
| | `checkpoints/`, `adapters/`, `.cache/`, `models/` | Nothing by default; safety nets for common places to put weights (`backend.models_dir` defaults to `~\.cache\kumaru\models`, outside the repo) |
| | `*.gguf`, `*.safetensors`, `*.bin`, `*.pt` | Weight files, wherever they land |
| Data | `data/*` plus four `!` rules | Your own datasets stay private; see below |
| Logs and local state | `logs/`, `*.log`, `.kumaru/` | Log files anywhere; `.kumaru/` is reserved for per-machine state (nothing writes it yet) |
| Editors / OS | `.vscode/`, `.idea/`, `.DS_Store`, `Thumbs.db` | VS Code, JetBrains, macOS Finder, Windows Explorer |

### The `data/` allow-list

```gitignore
data/*              # ignore everything directly inside data/ ...
!data/samples/      # ... except the samples folder
!data/samples/**    # ... and everything in it
!data/bench/
!data/bench/**
```

Committed: `data\samples\` (the tiny training examples the recipes use) and `data\bench\` (your golden questions, `golden.jsonl`). Anything else you put in `data\`, such as a scraped dataset or private chats, stays local by default.

It is written `data/*`, not `data/`, on purpose. git never looks inside an ignored folder, so `data/` followed by `!data/samples/` would not work. `data/*` ignores the folder's *contents*, which the `!` rules can then re-include.

## How to use it

```powershell
git status --ignored                       # also list what is being ignored
git check-ignore -v runs\bench\x\run.json  # which rule ignores this path (no output = not ignored)
git check-ignore -v data\bench\golden.jsonl
```

**Sharing a benchmark or training run.** `runs\` is never committed. Each run folder is self-contained, so zip the one you want to share:

```powershell
Compress-Archive runs\bench\20261010-120042-qwen36-nothink nothink.zip
```

`kumaru bench report` and `compare` work on an unzipped copy anywhere. To keep a few runs permanently, copy them outside `runs\` (for example `docs\results\`); a run folder holds only JSON files, so no rule catches them there.

**Sharing a fine-tuned adapter.** Adapters are weight files, so they belong on the Hugging Face Hub (or any file store), not in git.

## How to extend it

- **A new feature writes files.** Write them under `runs\<feature>\`, which is already ignored, rather than adding a rule. If they must live elsewhere, add the rule in the block of the program that produces them, with a comment saying which command creates the files.
- **A new committed data folder.** Add both `!data/<name>/` and `!data/<name>/**`.
- **Personal ignores** (your editor, tools only you use) belong in `.git\info\exclude`, which works like this file but is never committed.
- **Verify a change** with `git check-ignore -v <path>` on one path that must be ignored and one that must not.

## Failure modes

| Symptom | Likely cause | Fix |
|---|---|---|
| A file you meant to commit is missing from `git status` | A rule matches it: often `*.bin`, `*.log` or `models/` catching something unrelated | `git check-ignore -v <path>` names the rule. Add a `!` rule for that path, or `git add -f <path>` once (git then tracks it) |
| A file is ignored but still shows as modified | It was committed before the rule existed; rules never apply to tracked files | `git rm --cached <path>` stops tracking it and keeps the file on disk. Commit that |
| You committed weights or a large file by accident | The extension was not covered, or the commit used `git add -f` | Before pushing: `git reset --soft HEAD~1`, then unstage the file. After pushing, removing it requires rewriting history (`git filter-repo`); the GitHub push will usually have failed already for files over 100 MB |
| A new file in `data\` does not show up | `data/*` ignores it by design | Put shared data in `data\samples\` or `data\bench\`, or add an allow-list pair |
| `git status` lists `.impeccable\` or another tool's cache | A tool you use stores state in the repo, and the shared file has no rule for it | Add it to `.git\info\exclude` |
